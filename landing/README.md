# Лендинг

Лендинг: `index.html`, стили, скриншоты портала и версии на английском
(`en/`) и испанском (`es/`). Скриншоты снимает `capture.mjs` с работающего
портала — они не рисуются руками и потому не расходятся с продуктом.

Разворачивается отдельно от портала: у страницы нет ни базы, ни воркера,
ни состояния, и держать её рядом с приложением значит платить за это
ресурсами и рисками.

Страница о продукте для технического читателя — другая:
[docs/presentation.html](../docs/presentation.html). Она про устройство
и решения, лендинг — про то, что человек получит.

## Проверить локально

```bash
docker build -f landing/Dockerfile -t backlog-landing .
docker run --rm -p 8080:8000 backlog-landing
```

Контекст сборки — корень репозитория, а не этот каталог: страница живёт
в `docs/` и должна остаться в одном экземпляре.

## Развернуть на Railway

Через панель, один раз:

1. **New Project → Deploy from GitHub repo** → `Tools-n-Services/backlog-helper`.
2. В настройках сервиса задать переменную
   `RAILWAY_DOCKERFILE_PATH` = `landing/Dockerfile`.
   Без неё Railway возьмёт корневой `Dockerfile` — то есть соберёт портал,
   а не страницу.
3. **Settings → Networking → Generate Domain**.

Порт задавать не нужно: контейнер слушает и 80, и 8000 — оба варианта,
которые Railway ставит домену. Переменную `PORT` этому сервису платформа
не передаёт, поэтому полагаться на неё нельзя.

Через CLI, если он установлен и вы вошли:

```bash
railway link          # выбрать проект
railway up            # собрать и выкатить
railway domain        # получить адрес
```

## Обновить страницу

Правится `docs/presentation.html`, дальше обычный push: Railway пересобирает
сервис сам. Отдельного шага для лендинга нет.
